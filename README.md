# Электронный дом — проверка знаний

Next.js / React, Supabase Auth + PostgreSQL + private Storage, Vercel.

## Проверки и выпуск
Node.js 24 LTS (минимум 22.13). Скопируйте .env.example в .env.local и настройте публичные Supabase URL и ключ. Service-role ключ нельзя помещать в NEXT_PUBLIC_*.

    npm ci
    npm run dev
    npm run check
    npm audit

check запускает ESLint, TypeScript, тесты и production-сборку. Vercel выполняет те же проверки до публикации. GitHub Actions проверяет push и PR; Dependabot предлагает обновления зависимостей.

## База данных
Только для НОВОЙ БД: примените supabase/schema.sql, затем миграции по порядку. Для существующей БД применяйте только новые миграции. Повторное применение базовой схемы восстановит старые политики доступа!

Перед supabase/migrations/20260907_security.sql создайте резервную копию. Выполните миграцию внутри BEGIN / COMMIT. Существующие аккаунты и результаты сохраняются. Новые регистрации требуют подтверждения почты и одобрения администратора (разблокировки в Пользователях). Первого администратора назначают вручную через доверенную консоль БД, а не по специальному email.

Проверка RLS: BEGIN; содержимое миграции; tests/rls.sql; ROLLBACK;. Тесты создают временные профили и результаты, проверяют роли и обязательно завершаются откатом. После успешной проверки примените миграцию отдельно с COMMIT.

Пользователь видит свои неархивные результаты, администратор — все. Отключение аккаунта сохраняет историю, запрещает вход и отзывает refresh-сессии. Нельзя отключить себя или последнего действующего администратора. Архивация выполняется через archive_result; прямое удаление результатов клиенту запрещено.

## Резервные копии и хранение
Храните резервные копии вне git с доступом только владельцу. JSON-экспорт публичных таблиц является ЧАСТИЧНОЙ копией: дополнительно необходимы схема БД, Auth и файлы Storage. Проверяйте восстановление в отдельном проекте.

supabase/functions/quarterly-retention автоматически НЕ включается. Перед запуском постоянного удаления настройте полную резервную копию и согласуйте срок хранения. Функция проверяет принадлежность путей вложений и удаляет отдельные записи после успешного удаления файла. Серверные ключи не должны попадать в браузер.

## Аутентификация
Настройте минимум 12 символов в Supabase Auth и безопасную смену пароля. Сохраните подтверждение почты и защиту повторного использования refresh-токенов. CAPTCHA требует собственных ключей провайдера. Включите MFA владельца GitHub, Vercel и Supabase. Принудительная MFA внутри приложения здесь не реализована.

Восстановление пароля использует /?recovery=1, меняет пароль и завершает сессию. Production URL должен быть в разрешённых redirect URL Supabase. В production нет демо-входа или автоматического наполнения базы.

CSP запрещает встраивание в iframe, плагины и посторонние сетевые адреса. Inline-скрипты и стили пока разрешены для статической сборки Next.js; CSP с nonce требует перехода на динамический рендеринг.
